# Auditoría de integridad de cachés de CI

**Fecha:** 2026-08-17
**Alcance:** cachés de GitHub Actions (`.turbo`, store de pnpm), hash de entradas de Turborepo, cobertura de `outputs`, cachés no-Actions (BuildKit, Stryker, knip) y el workflow de retención (`cleanup.yml`).
**Método:** cada afirmación se sostiene con `file:line` o con un comando y su salida real. Todo hallazgo pasó por una verificación adversarial independiente; 12 candidatos fueron refutados y se listan al final para que nadie los reinvestigue.

---

## 1. Veredicto en una línea

**SÍ.** La caché puede hacer pasar un gate que debería fallar: se reprodujo, sobre la caché real del repo, una corrida de `turbo` con `Tasks: 2 successful / 2 cached / >>> FULL TURBO` y salida cero que dejó `infra/prisma/dist/src` en **0 archivos** — un artefacto vacío bendecido bajo un hash nuevo y servido indefinidamente (OC-2). El mecanismo se confirmó una segunda vez en un banco controlado: un commit que cambia únicamente `tsconfig.build.base.json` (`ES5 → ES2020`) obtuvo `cache hit, replaying logs`, exit 0, y un `dist` compilado con la configuración **anterior** (NAC-02).

Corolario igual de importante: el incidente que originó esta auditoría (PR #189, `TS2724 'TrackedLinkId'`) fue un **falso rojo**, y su vector de transporte quedó probado en vivo — el `restore-key` catch-all `${{ runner.os }}-turbo-` sirvió a los 6 jobs de CI una `.turbo` construida en `main`, contra **otro** `pnpm-lock.yaml` (AC-1).

**Límite honesto:** el vector de transporte está probado; la _génesis_ de la entrada rancia de `@core/domain` de aquel incidente no lo está. Las dos hipótesis que la explicaban (TH-1, TH-2) fueron refutadas empíricamente. Lo que sí está probado son tres caminos de génesis independientes para entradas envenenadas (OC-2, OC-3 local, TH-3 por escritura concurrente).

## 3. Los falso-verdes, aparte

> Un gate que no puede fallar no es un gate. Esta sección se separa a propósito: un falso rojo cuesta una corrida; un falso verde deja pasar un commit roto.

### 3.1 Falso-verde **probado** — acción inmediata

| ID         | Sev.     | Qué deja pasar                                                                                                                                                                                      | Prueba                                                                                                                                                                                                                                                                                                                                                         |
| ---------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **OC-2**   | CRITICAL | Una corrida de `build` completamente verde que produce **cero output compilado**, re-bendecida bajo un hash nuevo y auto-propagante                                                                 | Entrada `24c57450fd9c779a` escrita con 404 archivos y `dist/src` = 0; al re-servirse: `2 cached, 2 total / >>> FULL TURBO` y destrucción de un `dist` sano (18 → 0 archivos). A prueba de reparación: ni el propio build ni el `tsc -b` del consumidor lo reconstruyen                                                                                         |
| **NAC-02** | MEDIUM   | Un cambio de settings de compilador (`skipLibCheck`, `target`, `module`, `declaration`, `composite`) que ningún compilador ejecuta nunca; el `dist` que consume el gate viene de la config anterior | Repro end-to-end: config commiteada `ES2020`, artefacto servido `ES5 skipLibCheck=false`, exit 0. Amplificador que el hallazgo original no vio: el hash es **por paquete**, así que un commit mixto (config + 1 paquete) igual replaya los otros 78 desde caché — es un falso-verde parcial en _cada_ edición de config, mucho más alcanzable que el caso puro |

**Mitigación existente que sí funciona (no romperla):** `turbo run typecheck` (`ci.yml:44`) está correctamente hasheado — cada `typecheck` es `tsc --noEmit` sobre `tsconfig.json`, que extiende `tsconfig.base.json`, sí declarado como dependencia global. Los errores de tipo a nivel fuente se siguen detectando. El punto ciego de NAC-02 se limita a semántica de _emit_: `.d.ts`, `composite`, `target`/`module`/`moduleResolution`, `skipLibCheck` sobre `.d.ts` de dependencias.

### 3.2 Falso-verde **estructural, no observado**

- **AC-1** — la simetría es real: los mismos 28 artefactos `build` replayeados alimentan Build Check, el gate de 165 tareas de typecheck y el cierre de dependencias de Package Tests en una sola corrida, así que un `dist` rancio que conserve un export borrado pasaría los tres. **No encontré una instancia observada.** La dirección falso-verde queda marcada como NO VERIFICADA; la falso-rojo está probada.

### 3.3 Falso-verde **acotado o latente** — no bloquean código

- **AC-3** (MEDIUM) — el job miente `✅ Completed` semanalmente sin borrar nada, pero `needs.cleanup-caches.result` solo se consume en la tabla resumen (`cleanup.yml:292`). Ninguna branch protection, PR check ni gate de build lo lee. Costo real: crecimiento sin límite (174 cachés, 1939 artefactos al momento del incidente) y cero señal ante una regresión de permisos. **Advertencia:** arreglarlo **no** cierra el envenenamiento de turbo — la clave embebe `${{ github.sha }}`, así que el contenido rancio migra a una entrada de minutos de antigüedad en cada corrida y un filtro por `created_at < now-7d` nunca puede seleccionarlo (verificado: `rg -c 'Failed to delete cache Linux-turbo'` = 0 en las 5 corridas inspeccionadas).
- **NAC-05** (LOW) — el SARIF certifica una imagen que después se descarta y se reconstruye. Hoy no se pushea nada (32/32 instancias saltaron el push) y nada en el repo consume la imagen. Higiene a cerrar **antes** de retomar el workstream de containerización.

### 3.4 Falso-rojo / integridad (dañino, pero no deja pasar nada)

- **AC-1** — probado con el `TS2724` del intento 1 del run `32062485695`.
- **TH-3** — fallos espurios nondeterministas sobre fuentes limpias (2/11): `TS1010`, `TS2306`. Misma familia que el `TS2724` del incidente (un barrel a medio escribir).
- **OC-3** — `TS2307` en el consumidor, solo en workspace local; alcanzabilidad CI cero.
- **TH-4** — no es ni verde ni rojo falso: CI construye fielmente un árbol al que le falta el archivo. El daño es un link de sidebar roto que se despliega en cada build y una feature de 16 KB que existe solo en un disco, irrecuperable desde git.
