## Stack

| -------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `apps/api`     | Fastify 5 REST API (`type: "module"`)                                                                    | **dev**: `node --import tsx`. **prod**: per-package `tsc -b` emit to `dist` (NodeNext). |
| `apps/workers` | BullMQ background job processors                                                                         | Same: tsx in dev, NodeNext `tsc` emit in prod.                                          |

- **Build model (ADR-0017)**: production build is **transpile-only** per-package `tsc` emit to `dist` (NOT a single bundler). Backend (`apps/api`, `apps/workers`, `@core/*`) runs via **NodeNext** — the `.js` extension convention is **backend-only**. Next apps + frontend-only packages use `moduleResolution: bundler` = **extensionless** (fitness #26 blocks `.js`-on-`.ts` relative imports in frontend dirs).

## Module Resolution Model — the area this SDD change targets

The known defect this change addresses:

- Workspace package.json `exports` currently point **UNCONDITIONALLY at `dist`**.
- Dev/test/CI consumers that go through Node's `exports` resolver (`tsx`, `node:test`) land on `dist` even when `dist` is **not built** → resolution breakage.
- The fix space is conditional `exports` (dev/test → source, prod → `dist`) or an equivalent resolver-aware strategy that keeps NodeNext (backend) and bundler (frontend) models intact.

**Canon docs to read before designing the change**:

- `docs/technical/ADR-0017-production-build-bundler.md` (the build/emit decision)
- `CLAUDE.md` + the 4 auto-loaded canon children:
  - `docs/architecture/ARCHITECTURE_CANON.md` (Hexagonal · DDD · CQRS · UoW · Saga · DI)
  - `docs/development/CODING_STANDARDS.md` (TS strict, Result, naming, testing, JSDoc `@layer`)
  - `docs/security/SECURITY_CANON.md` (secrets/env, multi-tenant isolation)
  - `docs/observability/LOGGING_CANON.md` (logging factories, background scheduler, caching)
- The **26 CI fitness functions** in `CLAUDE.md §Automated Compliance Checks` (hard-zero each). Fitness #26 is directly relevant (frontend `.js`-import ban).

## Testing

**Three frameworks, strict domain boundaries. Jest is NOT allowed.**

| Layer                          | Framework    | Location / command                                                                      |
| ------------------------------ | ------------ | --------------------------------------------------------------------------------------- |
| Backend unit                   | `vitest`     | `apps/api/tests/unit/` — `pnpm --filter @apps/api test` (`vitest run`)                  |
| Backend unit (coverage)        | `vitest`     | `pnpm --filter @apps/api test:unit:coverage`                                            |
| Backend integration            | `node:test`  | `apps/api/tests/integration/` — `node --import tsx --test` (via `scripts/run-tests.sh`) |
| Backend all (unit+integration) | both         | `pnpm --filter @apps/api test:all`                                                      |
| Frontend                       | `vitest`     | `+ @testing-library/react` (admin components, client hooks)                             |
| E2E                            | `Playwright` | admin auth, client publishing                                                           |
| Mutation                       | `Stryker`    | `cd apps/api && pnpm exec stryker run` (vitest-runner, `coverageAnalysis: perTest`)     |

- **Test env**: vitest auto-loads `.env.test` via `setupFiles` (`apps/api/tests/setup-env.ts`, `apps/workers/tests/setup-env.ts`). On fresh clone: `cp .env.test.example .env.test`, point `DATABASE_URL` / `REDIS_URL` at local infra (`omnipost-infra`).
- **Integration tests need real services**: `pnpm db:up` (PostgreSQL + Redis) before running. Never skip because services are down — start them.

The project has extensive test coverage + a non-negotiable **0-defect obligation**. New/modified production code is **tests-first** (RED → GREEN → REFACTOR). Coverage targets: domain 90%, application use cases 85%, infra adapters 70%, routes 70%, provider adapters 75%.

## Conventions

- **Architecture**: Hexagonal (Ports & Adapters) · DDD · CQRS · Unit of Work (every mutating use case) · Saga (`defineSaga()` factory) · Dependency Injection (130+ tokens, composition root only).
- **Result type**: `Result<T, E>` — **never `throw` across layer boundaries**; domain/application are throw-free.
- **DI**: only the composition root (`apps/api/src/infrastructure/container/**` + `index.ts`, `apps/workers` own root) imports singletons / `new`s adapters. Everything else receives deps by constructor injection. Never `import { prisma }` outside the root.
- **JSDoc**: every `.ts`/`.tsx` file has a `@file` header; `@layer` is exactly one of `domain` / `application` / `infrastructure` (no other values). React components also carry `@component`.
- **Commits**: **conventional commits only**, **NO AI attribution / Co-Authored-By**. Commit/push ONLY when the user explicitly asks; ask at each batch close.
- **Dependencies**: all **exact-pinned** (no `^`/`~`); overrides are deliberate and audited (Edward dislikes overrides — each is tracked in backlog).
- **Docs**: all project docs live under `/docs/`. Never create `.md` files in `apps/`, `packages/`, `infra/` (only `CLAUDE.md` + `.claude/`). ADRs in `docs/technical/ADR-NNNN-*.md`.
- **Canon exceptions**: any canon violation needs a `// canon-exception: <scenario>:<ticket>` marker from the allowed list (Security canon + multi-tenant + DI composition-root rule have NO exception).
- **Tripwires**: pre-edit hooks block time-bomb/patch/workaround comments, sprint/phase refs in comments, cross-bounded-context imports, mass `sed -i` on imports. Bypass only via `canon-check:` citation or `omnipost-allow sensitive-edit` token.

## Environment Constraints (LXC dev box)

Dev runs on a Proxmox homelab LXC (101 infra / 102 dev, Tailscale MagicDNS). Hard limits that downstream phases (esp. `sdd-apply` / `sdd-verify`) MUST respect:

- **~9 GB RAM cap** on the dev container — cap heap on heavy operations.
- **NO `docker build` locally** — the 4 Docker images never built (backend runs via tsx, no emitted JS); containerization is PAUSED pending a real bundler decision.
- **NO full test suite at once** — run **single test files** with `--max-old-space-size` + a `timeout` wrapper. Running `pnpm test:all` unbounded risks OOM-kill.
- Migrations: always `pnpm db:up` first (start PostgreSQL + Redis), then migrate. Never skip a migration because "DB is not running".

## 0-Defect Gate (non-negotiable)

Every implementation ends at **0 error / 0 warning**, regardless of session length. Prohibited: deferring a failure as "pre-existing / out of scope", suppressing, or raising thresholds to mask. Final gate = `lint --max-warnings 0` · `tsc` · all 26 fitness functions · LXC-safe tests · all CI workflows green if pushed to main.
