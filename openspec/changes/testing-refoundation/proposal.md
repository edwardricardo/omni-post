## Intent

The repository carries 942 test files and 12,623 green tests whose verdict is not evidence: 20 node:test suites no runner reaches, 23 orphan test files, at least 10 files with two collectors, 272 blocks whose only assertion is existence, 114 runtime skips that turn a missing service into a pass, E2E and k6 never executed in CI, coverage measured in 1 of 86 configs, five required gates that cannot fail, and a 19-context merge gate (`strict: false`) in which an upstream red becomes a downstream "skipped" that GitHub counts as success. This change makes a green run evidence. Five frameworks (vitest, node:test, Playwright, MSW, k6) become one system through three shared contracts — **reach** (every test file has exactly one collector, run by a required check), **environment** (one script owns services, identities, ports and readiness for local and CI alike), **verdict** (every layer emits an exit code and a readable report, and the merge gate composes them with no evadable `needs:`) — plus shared tooling so all five layers speak about the same `Post`. The order is the signed one: the decorative is demolished first and listed before deletion, the frameworks are re-founded on the floor that survives, the untested surface is covered, and mutation testing returns last as the only tool that verifies the both-directions rule at scale.

## Design principles

Stated once so reviewers check every work unit against them instead of re-deriving them per slice.

| #   | Principle                                                                                                                                                                                                                                                                                                                                              | Where it bites                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P1  | **A test proves in both directions**: it fails when the behaviour is not met and passes when the code meets it. The same rule as "a gate is born with its red demonstrated", applied per test. It is the criterion for demolishing and for building.                                                                                                   | Every new test in 6.N (hard probe RED with the subject gutted is its acceptance); Phase 7 measures it at scale.                                        |
| P2  | **Decorative criterion**, any one of four, proven per file and listed before deleting: (a) asserts only existence; (b) points at something that does not exist; (c) skips itself under the conditions CI provides; (d) cannot fail by construction. Hard probe for doubt: gut the implementation — if the test stays green, it is decorative.          | Phase 2 classifier, ledger, probe, lint rules; nothing is deleted without a ledger row and Edward's approval (WU-2.5).                                 |
| P3  | **Replace a default with a refusal** (amendment A3). Every measured defect was hidden by a fallback: `__ENV.BASE_URL \|\| localhost`, `run-tests.sh` sourcing root `.env`, `skipIfApiUnavailable`, `dbAvailable = false`, `$queryRaw → []`. A documented fallback with a stated reason that throws when both inputs are absent is the legitimate form. | WU-1.6, 4b.1-4b.5, 4.1, S.3, 6.K2, 6.M2, 3.13 — about fifteen work units share this one decision.                                                      |
| P4  | **Every gate is born with its red demonstrated** on the complete step (planted violation, exit ≠ 0, byte-exact restore verified by checksum, re-green), never on the step's node body alone.                                                                                                                                                           | All of Phase 3, every fitness change, every lint rule, the tracker's Gates table.                                                                      |
| P5  | **Fail closed; a dead scope is worse than no check.** Zero configs, zero globs, zero models, an empty rules array, a missing directory — each exits 1 rather than printing a clean zero.                                                                                                                                                               | `packages/test-contracts` (reach, scopes, floors, identity, verdict, denominator); the ruleset drift gate (evaluate-mode rulesets are invisible, C18). |
| P6  | **The PR that moves a metric updates the tracker in the same PR.** Never a separate tracker PR (a re-plan is the one exception and is logged in Decisions).                                                                                                                                                                                            | `TESTING_REFOUNDATION.md` Metrics/Work units/Gates/Declared gaps tables; `scripts/testing/metrics.mjs` re-derives every row.                           |

## Approach

**The unit is the composition of the merge gate, not a runner** (signed point 10). Frameworks do not call each other; they share three contracts and one tooling layer.

| Contract        | Mechanism                                                                                                                                                                                                                                                                                           | Verified by                                                                                                                                                                                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Reach**       | Filename suffix routes: `*.test.ts(x)` vitest · `*.integration.test.ts` services tier · `*.live.test.ts` live tier · `*.spec.ts` Playwright · `*.k6.js` k6; `*.fixture.ts`/`*.test-helpers.ts` no collector by design. Disk set = `git ls-files` repo-wide.                                         | `packages/test-contracts` asks each runner what it collects: `disk − ⋃ collected-by-a-required-job = ∅`, exactly one collector per file, quarantine `head ⊆ base`. Job "Test Contracts" in `fitness.yml`.                                                           |
| **Environment** | `scripts/test-env.sh` owns everything from "services reachable" onward; starts neither Postgres nor Redis (CI `services:` blocks; the infrastructure LXC locally). The contract is over what runs — image major, `vector` extension, database name, roles, ports, readiness — checked by preflight. | Same command in `ci.yml`, `performance.yml`, Playwright `webServer` and local; #46 identity gate; three safety properties: never the dev database (only `omnipost_test`), never dev Redis queues (DB 15), never a live dev server (ports + 10, bound port refused). |
| **Verdict**     | Each layer: exit code + machine- and human-readable report. Merge gate: all contexts required, `strict` policy, no job-level `if:` that can skip, `needs:` only with `!cancelled()` and a step reading `needs.<id>.result`, no `continue-on-error`, no `\|\| true` on a gate tool.                  | Committed `.github/rulesets/main.json`; #44 V1-V7 (static) + V6 drift from `GET /repos/{o}/{r}/rules/branches/main` failing closed on an empty array; every gate red-proven on the full step.                                                                       |
| **Tooling**     | `@test-utils/domain` (aggregates via `create()`, deterministic ids and clock), `@test-utils/wire` (OpenAPI-typed DTOs, MSW server, handlers, sidecar), `@test-utils/persistence` (Prisma double whose raw SQL throws, Redis double, seeds). Route apps built in `apps/api/tests/support/`.          | Dependency-cruiser gate: nothing under `src/**` imports `@test-utils/*`; lint gates on local builder names and `PrismaClient` casts; migrations prune their suppressions.                                                                                           |

**Framework verdicts** (signed point 11; confirmed by exploration §3 and research): vitest/RTL/coverage stay; Playwright stays (chromium only as gate); MSW becomes the only HTTP double; k6 stays only if load blocks merges after calibration, else deleted; Jest leaves with `@storybook/test-runner`; mutation returns after coverage. The one open fork — node:test vs vitest for the services/live tiers, 108 files — is decided by WU-4.X1's nine metrics and WU-4.X2's hypotheses H1-H5 (H4: any mock, alias or stub added to make Prisma or the saga engine run under vite fails it by the no-patches rule). The suffix names the tier, not the runner, so the router survives either outcome.

## Rollback plan

- **Per slice**: stacked-to-main, one autonomous work unit per PR, each independently revertible with a plain `git revert`. Gates land with their red demonstrated, so reverting a gate PR restores the previous check, never a blind one.
- **Deletions**: every whole-file deletion is backed by an approved ledger row; git history retains the bytes; a suite removed by mistake re-enters through `quarantine.json` (until WU-1.15) or directly by suffix afterwards.
- **Verdict switchover**: the classic required checks are re-creatable from the mirror committed at WU-1.10 (`.github/rulesets/main.json` with the 19 contexts, `strict: false`); the ruleset is deletable with `gh api -X DELETE …/rulesets/{id}` (Edward).
- **Toolchain**: one PR per family; reverting the catalog line and the lockfile restores the previous version; the hold table documents why a family was not moved.
- **Environment**: `scripts/ci-setup-test-env.sh` is deleted only in the PR that makes every workflow call `test-env.sh`; that PR reverts as a unit.
- **Production**: the Telegram seam is one PR, refused under `NODE_ENV=production`, revertible alone; the contrast fix is one CSS line.
- **Coverage floors**: `autoUpdate` only raises; a mistaken floor is lowered with a `canon-exception` marker under the scenario introduced by WU-2.0, visible in review.
