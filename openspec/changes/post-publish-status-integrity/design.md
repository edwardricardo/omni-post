# Design: post-publish-status-integrity (N-COR-1) — rev 2

**Inputs**: `proposal.md`, `pre-propose-decisions.md` (Q1–Q5, honoured verbatim), `specs/post-publish-status-promotion/spec.md` (R1–R9), rev 1 + the design-gate report (2 CRITICAL, 5 WARNING, 5 SUGGESTION). Every claim re-read in the tree at `31e2a2ad`.

**What rev 2 changes.** The gate confirmed rev 1's load-bearing claims (version advances only in `doUpdate`; no command-id dedupe in the bus; tenant/RLS inherited via `runAsSagaTenant` → `withTenantContext` + `PrismaUnitOfWork`; total success decidable from wait-step counts; D4 within canon, no ADR). Those stand. Rev 2 adds **D9** (started-event delivery, C1), **D10** (transaction abort, C2), **D11** (a new finding: in-transaction outbound delivery), corrects D4's writer inventory (W1), adds the emptiness guard (W2), the missing assertions (W3), the content-preservation mechanism (W4), the eviction residual in its true terms (W5), and folds S1–S5.

## Technical Approach

The saga step becomes a thin forwarder of the publish **outcome** into a new command, `post.complete-publishing`. Its handler delegates to `CompletePostPublishingUseCase` (`packages/core/posts`), the single writer: load once, `startPublishing()` then `markAsPublished()` (Q4), save once inside one Unit of Work. `doUpdate` persists `status` + `publishedAt` and writes `PostPublishingStarted` + `PostPublished` to the outbox in that transaction (`PrismaPostRepository.ts:776-778`). Two things rev 1 left implicit are now explicit: the transaction **aborts** on any `err` the use case returns (D10), and the use case dispatches **nothing in-process** — the outbox relay is the only delivery path, after commit (D11). `PostPublishingStarted` stays internal (D9). `post.update` loses `status` and becomes strict (D6).

## Interfaces / Contracts

// packages/core/domain/src/repositories/Repository.ts
export interface UnitOfWork {
  executeInTransaction<T>(fn: () => Promise<T>): Promise<T>;              // unchanged
  /**
   * SHIPPED AS A MULTI-LINE BLOCK, deliberately — do not collapse this to one
   * line. Fitness #4 excludes comment lines only when they START with `*` or
   * `//` (`grep -vE "^[^:]+:[0-9]+:\s*(\*|//)"`), so a single-line `/** … a
   * throw propagates. */` opens with `/` and is counted as a `throw ` hit in
   * `packages/core`, taking #4 off hard-zero. Measured during apply: the
   * one-line form scores 1 at `Repository.ts:183`; the multi-line form scores 0.
   * The shipped contract is the block at `Repository.ts:183-206`:
   * `ok(value)` COMMITS and is returned unchanged; `err(error)` ROLLS BACK and
   * is returned unchanged as a value; a genuine raised failure propagates
   * untouched and is never converted into an `err`.
   */
  executeResultInTransaction<T, E>(fn: () => Promise<Result<T, E>>): Promise<Result<T, E>>;
}

**Use-case order (S1, S3, W2 — stated once).** _Before the UoW, no I/O:_ invalid `postId` → `VALIDATION_FAILED` · `channels.length === 0` → `VALIDATION_FAILED` ("a vacuous total is not a publish" — `every()` is true on `[]`, so the guard precedes it) · any `success === false` → `NOT_IMPLEMENTED` ("partial outcome is N-COR-2"). _Inside `executeResultInTransaction`:_ `findById` → `NOT_FOUND` · `isPublished` → `ok({applied:false})` (before the token: the promotion outdates its own token) · `expectedVersion` supplied and ≠ loaded → `CONFLICT` · resolve providers (D7) · `isPublishing ? skip : startPublishing(providers)` (`InvalidStateTransitionError` → `FORBIDDEN`) · `markAsPublished(byChannel)` (→ `FORBIDDEN`) · `save()` → on `err`: `saveResult.error instanceof VersionConflictError` → `CONFLICT`, else `INTERNAL_ERROR` — **both roll back** (S2: narrowed on the Result, not caught) · `clearDomainEvents()` · `ok({applied:true, …})`. _Outer `try/catch`_ (genuine throws: tx timeout, connection, the tenant guard's `TenantContextMissingError`): `classifyPersistenceFailure` (`UseCase.ts:143-152`, precedent `RestoreProjectUseCase.ts:65-76`) → `TRANSIENT_FAILURE` / `INTERNAL_ERROR`.

**Step contract.** `ScheduleStepData { jobIds; channelIds; channelCount; scheduledAt }`, `channelIds.length === jobIds.length`, same order. The step refuses (outcome `failed`, named reason, **no command**) on: missing `accountId`, missing/short `channelIds`, or any D1 count precondition. A persisted saga from before this change lacks `channelIds` and fails closed. `cmd-{sagaId}-update-post-status` stays deterministic (#7).

## Residuals and backlog rows (named, not hidden)

- **W5 — evicted completed job.** The publish consumer sets no `removeOnComplete` (`publishWorker.ts:193-196`), so the adapter default `{ count: 100 }` applies (`consumer-adapter.ts:60`); `getJobStates` reads a missing job as `failed` (`queue-adapter.ts:219-223`); the **wait step** then fails (`saga.ts:829-834`), the saga FAILs post-pivot, and the post stays DRAFT while the provider holds it — the N-COR-1 observable through another door. The harness stub (`sagaCrashRecovery.test.ts:108-113` and this suite) hides it by construction; only the live tier with >100 completions between a job's completion and the poll could reach it. Backlog: explicit retention outliving the poll window, or a reader that distinguishes evicted from failed.
- **W4 — lossy mapper.** `PostAggregateMapper.toDomain:107-121` drops any media row whose `MediaAttachment.create` fails, and `doUpdate:741-746` then deletes those rows; every `save()` inherits it, this one included. Backlog: fail closed (`reconstitute`), never drop.
- **W1 — direct status writers.** `SchedulingPostHandlers.ts:254,:354` bypass the aggregate and the version; reschedule has no status guard. Backlog.
- **D11 class.** Sibling Post use cases dispatch in-process inside the transaction, reaching an outbound-delivery handler pre-commit and double-delivering. Backlog (class), not this change.
- **D10 class.** The canon pattern's `let result` capture hides `err` from the UoW, so any multi-statement save that fails JS-side after its first statement commits partially. Migration of the 56 callers to `executeResultInTransaction` is mechanical → backlog. - Pre-existing: `SchedulePostUseCase.ts:192` counts `incrementPostPublished` at schedule time (no metrics port here until adjudicated); `post.update` production-dead after this change (flag, not delete); `markAsPublished(providerResults)` keyed by channel id (N-COR-2 naming); `PUBLISHING` never durable, edit window open during publish-now (Q4 consequence); `openspec/config.yaml` cites `#1-#40`, the suite has 41.
