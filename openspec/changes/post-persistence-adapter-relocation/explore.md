## 1. Context & motivation

N-COR-8 (`post-publish-partial-failure`) makes `PostChannelPublication` the only source of publication truth, and its D2 requires the **publish worker to write that outcome through the same `@core/posts` use case the API uses**, resolved from the workers' own composition root over a tenant-guarded client. That is the whole point: both isolation layers must hold on the worker's write — layer 1 (`$extends` guard) injecting `where.accountId`, layer 2 (RLS) binding `app.account_id` as the transaction's first statement.

The four pieces that make that possible — aggregate hydration, the version CAS, the outbox write and the GUC-bound transaction — live today inside `apps/api/src` and are therefore unreachable from `apps/workers`. D1 (`:60`) already refutes the cheap alternative: making the use case's port implementable by the existing `packages/adapters/db-prisma` `PostRepository` (a `@ports/core` DTO factory under `SYSTEM_TENANT_SCOPE`, no aggregate, no CAS, no outbox) "IS the relocation renamed".

**This change owns the MOVE and the WIRING only.** No publication-record logic, no schema, no worker container. N-COR-8 D1 states what it must leave true afterwards: `apps/api` byte-identical in behaviour, `apps/workers/src/container/workerContainer.ts` still `workerPrisma` only.

**The approach is not speculative — it already exists in this repo.** `PrismaMentionRepository` (`packages/adapters/db-prisma/src/MentionRepository.ts`) is a class-based `@core/domain` port adapter living inside db-prisma, exported from the barrel (`src/index.ts:41`), constructed by a WORKER (`apps/workers/src/mentionIngestWorker.ts:430`: `new IngestMentionUseCase(new PrismaMentionRepository(options.prisma))`) and unit-tested from `apps/api/tests/unit/infrastructure/adapters/PrismaMentionRepository.test.ts:10` through the root specifier. That is precisely the shape this change produces, proven end-to-end.

### 2.5 Structural note

`packages/adapters/db-prisma/src/` is **flat today** (12 files, no subdirectories). D1 mandates `src/{post,outbox,unitofwork}/`. D1 is binding, so follow it — but the divergence from the package's own convention should be a deliberate sentence in the proposal, not an accident. ## 8. Recommended approach

**A**, with four amendments this exploration establishes:

1. **`PrismaUnitOfWork(prisma, tenantProvider, options?)`** — three parameters, options last, preserving the five positional call sites (§2.2a).
2. **`PrismaPostRepository(prisma, outboxWriter, tenantProvider)`** with `tenantProvider` **required**; the 7 one-argument test constructions are updated explicitly (§2.2b).
3. **Barrel re-export from `src/index.ts`; every consumer imports the root specifier `@adapters/db-prisma`** — never a subpath (§2.4).
4. **The relocated files keep a guard.** Extend #40 Part B's site scope to `packages/adapters/db-prisma/src` (admitting the injected derived form beside `getAmbientGucScope()`), extend #23's scope to the same directory, and extend `tenantTransactionNesting.test.ts`'s `walk` to it as well. Measured cost: **#3 and #5 extend for free (0 hits); #23 costs exactly ONE new audited-safe exception** — `packages/adapters/db-prisma/src/resilience.ts:308`, `prisma.$queryRaw\`SELECT 1\``, a connection health probe touching no tenant table.

Amendment 4 is the one worth defending. Without it the change nets **negative** guard coverage: three `withGucBoundTransaction` sites, a `set_config` raw statement and a nesting adjudication all leave every gate that watches them, while every counter still reads zero. That is precisely the failure mode `CLAUDE.md` opens by naming, and this change is the moment it is cheapest to prevent.

## 11. Open questions (technical — for propose/design, not for Edward)

1. **`TenantContextProvider` or a narrower port?** D1 says provider + `resolveGucScope`. A `GucScopeProvider { scope(): string | undefined }` would be narrower, but `resolveGucScope` already exists and takes the provider — recommend following D1 exactly, no new abstraction.
2. **Does `PrismaUnitOfWork.getTransactionClient()` stay `static`?** 16 adapters across `apps/api/src` call it statically. It must keep working identically after the move — the shared `AsyncLocalStorage` is now created inside a package loaded once per process. Confirm no dual-instantiation path (source vs `dist`) can produce two storages; the root-specifier-only rule (§2.4) is what guarantees one.
3. **Does #40 Part B accept `resolveGucScope(this.tenantProvider)` directly, or should the class expose a named private accessor** (e.g. `private gucScope()`) so the grep stays a single token? The accessor keeps the gate simple and self-documenting — recommended.
4. **`tenantTransaction.ts` stays in `apps/api`** (it wraps `getAmbientGucScope()` for API-side callers) — confirm it is not also needed worker-side by N-COR-8.
5. **Where do the three unit suites live?** §5's fork. Recommendation: keep in `apps/api/tests/unit/`.
