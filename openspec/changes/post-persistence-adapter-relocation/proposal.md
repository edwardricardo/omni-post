# Proposal: Relocate the Post persistence adapters to `@adapters/db-prisma`

**Change** `post-persistence-adapter-relocation` · **Branch** `workstream/post-persistence-adapter-relocation` (base `main` @ `c23ec2c8`) · **Input** `explore.md` (status done, gate PASS) · **Binding** N-COR-8 `openspec/changes/post-publish-partial-failure/design.md` §D1 (`:54-60`) and §D2 (`:62-68`), rev 3.2.

## Intent

N-COR-8 D2 requires the publish worker to record publication outcomes through the same `@core/posts` use case the API uses, resolved from the workers' own composition root over a tenant-guarded client, with both isolation layers holding on that write: layer 1 (`$extends` guard) injecting `where.accountId`, layer 2 (RLS) with `app.account_id` bound as the transaction's first statement. The four pieces that make that write possible — aggregate hydration (`PostAggregateMapper`), the version CAS and outbox write (`PrismaPostRepository` + `PrismaOutboxWriter`) and the GUC-bound transaction (`PrismaUnitOfWork`) — live in `apps/api/src` and are unreachable from `apps/workers`. D1 (`:60`) already refutes the shortcut of teaching db-prisma's DTO `PostRepository` to do this: it "IS the relocation renamed". This change is that prerequisite, signed by Edward on 2026-09-16 as its own change: the MOVE and the WIRING, nothing else. The shape is not speculative — `PrismaMentionRepository` already is a db-prisma class adapter of a `@core/domain` port, barrel-exported (`src/index.ts:41`), constructed by a worker (`mentionIngestWorker.ts:430`) and unit-tested from `apps/api/tests/unit` through the root specifier.

## Approach

**A — D1 with four amendments** (explore §8):

1. `PrismaUnitOfWork(prisma, tenantProvider, options?)` — options LAST. Taken literally, D1's `(prisma, tenantProvider)` silently reinterprets `HARD_DELETE_TX_OPTIONS` (`setupProjectUseCases.ts:71-74`) as a provider on the Serializable hard-delete path.
2. `tenantProvider` REQUIRED on `PrismaPostRepository`. An adapter that silently binds no tenant is the fail-open shape this repo exists to prevent; the 7 breaks are planned, not discovered.
3. Barrel + root specifier only. Measured: `tsconfig.base.json:143` maps `@adapters/db-prisma` ROOT only (no `/*` wildcard, unlike every `@core/*` entry), `moduleResolution: bundler` with no `customConditions`, zero subpath imports in the tree. A subpath specifier falls through `paths` onto `default: ./dist/*` and breaks the dev/test/CI source-resolution mode ADR-0017 §1c and fitness #27 protect.
4. The relocated files keep a guard (Fitness table below). Without it the change nets NEGATIVE guard coverage — three `withGucBoundTransaction` sites, a `set_config` statement and a nesting adjudication leave every gate that watches them while every counter still reads 0. That is the "dead scope = infallible gate" class `CLAUDE.md` opens by naming.

**Correction to Amendment 4, measured in this phase (deviation from explore §8 / handoff item 4).** `PrismaUnitOfWork.ts:105` is `` tx.$queryRaw`SELECT set_config('app.account_id', ${scope}, true)` `` — a TAGGED TEMPLATE. Fitness #23's regex is anchored on `\(`, so it has NEVER matched this line: the `/unitofwork/PrismaUnitOfWork\.ts` exception is inert today (SMELL-111's class — 6 known invisible sites), and N-COR-8 D1's S4 premise ("the exception name goes stale") assumed a live line. `packages/adapters/db-prisma/src/resilience.ts:308` (`` prisma.$queryRaw`SELECT 1` ``) has the same shape. Consequences: (a) #23's scope extension is still real — its red path is a paren-form `$queryRawUnsafe(` planted in the relocated UoW: 0 under the old scope, 1 under the new; (b) the UoW exception is RE-PATHED with an honest comment (inert until SMELL-111 closes), never silently carried; (c) NO exception is added for `resilience.ts:308` — it would be a second inert line, the SOLO GORDO class the explore itself flags for `sagaTenant.ts`. It is named in the #23 comment block as the audited-safe db-prisma site SMELL-111's closure must enrol (B3).
